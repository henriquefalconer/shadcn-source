# shadcn archive

A pinned, self-contained mirror of the shadcn/ui registry plus four community
registries — components, blocks, examples, fonts, themes, docs, and the official
shadcn Agent Skill. Everything needed to read, copy, or run these components is
in this directory.

`registry/`, `assets/` and the index files are generated by `./bootstrap.sh`
from upstream.

## What's here

| path | contents |
| --- | --- |
| `registry/` | Every component's source, extracted from registry JSON. Browsable. |
| `registry/shadcn/<style>/` | 27 style trees: 3 bases × 8 themes + 3 legacy styles |
| `registry/{react-bits,magicui,animate-ui,ai-elements}/` | Community registries |
| `docs/` | 108 documentation pages as markdown + `llms.txt` |
| `skills/shadcn-ui/` | The official shadcn Agent Skill, verbatim |
| `skills/shadcn-archive/` | Agent skill for working from this archive — start here |
| `assets/` | Vendored images, video, and 172 self-hosted woff2 font files |
| `upstream/` | Full upstream repo clone (source of truth, incl. 312 MDX docs) |
| `INDEX.tsv` | 2,098 items, greppable. Local equivalent of `shadcn search`. |
| `INDEX.json` | Full per-item records: deps, registryDependencies, local file paths |
| `COVERAGE.md` | The five coverage metrics, measured |
| `GAPS.md` | Everything missing, shimmed, or unverified — read before trusting coverage |
| `_verify/` | Build + verification harness (node_modules, lockfile, Vite app) |
| `_work/` | Fetch/analysis scripts and raw registry JSON |

## Finding something

```bash
grep -i "combobox" INDEX.tsv                 # search by name/description
grep -P "\tblock\t" INDEX.tsv                # all blocks
jq '.items[] | select(.name=="button")' INDEX.json
```

Then read the file directly out of `registry/`.

## Understanding the 27 styles

They are **3 component bases × 8 themes**, plus 3 legacy styles.

- **Bases** (different underlying primitive library): `radix`, `base` (Base UI),
  `aria` (React Aria)
- **Themes**: `vega nova maia lyra mira luma sera rhea`
- **Legacy**: `new-york`, `default` (Tailwind v3 era), `new-york-v4`

**All 24 are genuinely distinct source trees.** The theme is *not* only CSS: the
published registry bakes Tailwind utilities into each component, so switching
theme changes the `.tsx` itself. Measured: 57 of 60 `ui/` files differ between
`base-vega` and `base-nova` (e.g. `rounded-md` → `rounded-lg`, `shadow-xs`
dropped). Only 427 of 6,370 archived source files are byte-identical duplicates.

Changing **base** additionally changes the imported primitive library
(`@base-ui/react/button` vs React Aria's composed implementation).

`new-york-v4` is the only style with the complete set of examples, internal
components and themes. The 24 modern styles publish ui + fonts + 27 blocks. That
is upstream's actual shape — see `COVERAGE.md` for how it was verified.

## Running the verification harness

```bash
# serve the archive (loopback only)
_verify/node_modules/.bin/vite --config _verify/vite.config.ts

# prove it works with zero network
sandbox-exec -f _work/verify.sb _verify/node_modules/.bin/vite --config _verify/vite.config.ts
WORKERS=6 sandbox-exec -f _work/verify.sb node _work/harness/run-c5.mjs
```

`_work/verify.sb` is a macOS Seatbelt profile that denies all networking except
loopback. The runner refuses to start if a leak check shows the sandbox isn't
actually blocking — a proof from a porous sandbox is worthless.

## Re-extracting (important)

`_work/extract.mjs` regenerates `registry/` from the pristine raw JSON, which
**reverts the local-asset rewrites**. If you run it, you must follow with:

```bash
node _work/flatten.mjs          # collapse redundant nesting
node _work/reapply-rewrites.mjs # re-point assets and fonts at local paths
```

Both are idempotent.
